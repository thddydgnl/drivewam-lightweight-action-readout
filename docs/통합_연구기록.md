**핵심 주장 (근거 강도 순)**
1. **상상이 필요하다.** 월드모델이 미래를 *한 번* 상상한 표현(first)이 관측만 처리한 표현(current)보다 action readout에 훨씬 유리하다.
   - NAVSIM: +3.3 PDMS
   - PhysicalAI: ADE −0.11m
   - 반면 상상을 끝까지(terminal) 해도 더 나아지지 않는다.
2. **속도.** 상상 1패스 + 작은 head로, 반복 action 생성과 비슷한 품질을 1/2.2–1/12의 지연으로 낸다(공정한 최소 단계 기준 B\* 대비 0.45×, 0.16×).
3. **규모.** head 학습 데이터 규모가 결정적이다(두 벤치마크 모두 4k → 20k → 그 이상에서 격차가 줄었다).
4. **기억·언어.** 연속 주행 설정에서 기억(과거 chunk)과 언어 안내도 readout에 쓰인다(각 ADE 0.02–0.045m). 다만 상상 효과보다 작다.
5. **방법론.** 공식 single-seed 평가는 seed 선택에 민감하다(PhysicalAI B10 ADE 0.821–0.930). NAVSIM에서는 백본이 학습 장면을 기억해 navtrain 내부 검증이 왜곡된다.

**쓰면 안 되는 주장:** "학생이 B10보다 정확하다." PhysicalAI의 정확도 우위는 상당 부분 결정적(평균) 예측 효과다. B10 4개 표본 평균과 비교하면 ADE는 대등하고 FDE는 0.1m 못 미친다(§6.3).

## 1. 문제 정의와 가설

- **질문:** 이미 학습된 주행 WAM(DriveWAM)의 backbone을 재학습하지 않고, 어느 시점·깊이의 내부 표현으로 반복 action denoising을 대체할 수 있는가? 속도와 품질은 어떻게 되는가?
- **배경:** DriveWAM(Wan2.2-TI2V-5B 기반, 6.24B)은 미래 영상 latent를 몇 단계 denoising한 뒤 action을 10단계 flow matching으로 생성한다. action 생성이 지연의 큰 부분을 차지한다(논문은 H20에서 765ms라고 보고). 원 아이디어는 [연구 아이디어 문서](DriveWAM_Lightweight_Action_Readout_Research_Idea.md)에 있다.
- **사전 가설(NAVSIM 사전등록 기준)**
  - H1/H3(실용 목표): head가 B10·B\* 대비 품질을 유지하면서 B\*보다 충분히 빠르다.
  - H2: 여러 깊이 표현이 단일 깊이보다 낫다.
  - H4: 상상 시점(current / first / terminal)에 따라 readout 품질이 다르다.

## 2. 방법

### 2.1 고정 백본과 표현 추출
- DriveWAM checkpoint를 그대로 쓴다(NAVSIM용, PhysicalAI용 각각 공개 checkpoint). 공식 추론 코드를 비트 단위로 재현한 rollout에서 block 출력을 hook으로 읽는다.
- **시점**
  - current: 관측 프레임을 처리(등록)하는 패스. 상상이 없다.
  - first: 미래 latent의 첫 denoising 패스. 노이즈에서 한 번 상상한다.
  - terminal: 마지막 미래 denoising 패스.
- **깊이:** layer [10, 20, 30](0-based [9, 19, 29]). 각 layer의 영상 token(NAVSIM: 해당 해상도 token, PhysicalAI: 112 token × 3072).
- **조기 종료:** 학생은 first 패스 직후 멈춘다. 나머지 영상 denoising과 action 생성을 모두 건너뛴다. hook 비간섭과 조기 종료 feature = 전체 실행 중 feature(비트 단위)를 두 벤치마크 모두에서 확인했다.

### 2.2 학생 head (SF3)
- 구조
  - layer별 query pooling(query 16, 폭 512, LayerNorm → Linear 3072→512 → 8-head attention → 가중 합)
  - ego MLP와 융합
  - residual MLP
  - 시간 step embedding + FP32 출력층
- 출력
  - NAVSIM: 8 pose(4초, 2Hz)
  - PhysicalAI: 40스텝(4초, 10Hz) × (dx, dy, dheading)을 quantile 정규화
- 손실: 위치 Huber + 0.2 × heading(1−cos) + 0.1 × 정규화 delta Huber.
- 학습 protocol(v2 이후 고정): 40 epoch, AdamW 3e-4, wd 0.01, batch 32, warmup 5% + cosine, 마지막 checkpoint 사용(평가 세트로 선택하지 않음), 예측은 배포와 같은 batch 1.
- **PhysicalAI 전용 사항(사전등록 변경 9)**
  - 데이터의 action은 clip 시작 좌표계의 변위다.
  - head는 chunk 시작 차량 좌표계로 예측한다. 이미 등록된 실제 action에서 누적한 heading으로 회전한다. 이 정보는 모든 방법이 기억으로 받는다.

### 2.3 비교 기준
- **B10:** 공식 설정(영상 denoising + action 10단계).
- **opt 기준:** 마지막 action cache 패스(출력에 영향 없음)를 생략하고 단계 수를 줄인다(B10/B05/B03/B02/B01-opt). raw와 출력이 비트 단위로 같음을 확인했다.
- **B\***: dev에서 품질 기준을 통과한 opt 기준 중 가장 빠른 것. 학생이 "그냥 단계를 줄인 것"보다 나은지 공정하게 비교하려는 목적이다.
- **참고:** ego-only head, CV(등속).

### 2.4 평가 원칙 (두 벤치마크 공통)
- **사전등록:** 세트 분할, B\* 규칙, 판정 기준, 학생 사양을 결과 전에 고정했다. 실행 중 변경은 결과 전에 기록했다. final은 1회만 평가했다.
- **통계:** 군집 단위 paired bootstrap 2,000회(NAVSIM: 로그, PhysicalAI: NVIDIA chunk).
- **지연:** 같은 세션에서 장면/clip마다 모델 순서를 바꿔 번갈아 3회 측정했다. 판정은 비율로 했다(공유 호스트라 절대값이 날마다 다르다). 재는 구간은 벤치마크마다 다르다.
  - NAVSIM(policy 지연): policy 호출 한 번. 메모리에 있는 카메라 프레임에서 궤적까지이며 VAE 인코딩과 관측 패스를 포함한다. 경로 명령 문장 4개의 임베딩은 미리 계산했다.
  - PhysicalAI(결정 지연): 실제 기록 등록이 끝난 뒤부터 action chunk가 나올 때까지다. VAE latent와 안내 문장 임베딩은 미리 계산해 재지 않았다.
- **재현성 검증:** 원본 대비 비트 동일성(rollout, opt, 공유 rollout, hook, 조기 종료, 온라인 = 오프라인 학생)을 확인했다.

**실행 중 기술 문제와 해결 (재현 시 참고)**
- torch 2.9 + cuDNN 9.10에서 bf16 Conv3d가 극단적으로 느렸다(Qwen3-VL patch embed 1회 10.5s). 같은 수학의 `F.linear`로 바꿔 0.3ms가 됐고, FP32 기준 대비 오차도 같다.
- 원본 PhysicalAI 평가 코드는 문장 임베딩을 GPU에 무기한 캐시한다. 24GB GPU에서 메모리 부족이 나서 clip마다 캐시를 비웠다(값 동일).
- DriveWAM 태깅 스크립트(dev 선별용 VLM)는 24GB에서 메모리 부족이 나고 50 GPU시간 이상 걸릴 것으로 추정됐다. 그래서 dev를 무작위 val(D2)로 바꿨다.
- head 예측의 batch 크기가 BF16 출력에 영향을 줬다(NAVSIM, cm 단위). 그래서 batch 1과 FP32 출력층으로 고정했다.

## 5. NAVSIM 결과

### 5.1 백본 기억 효과 (처음 보는 장면이 필요한 이유)

| 모델 | navtrain head-val PDMS / ADE4 | navtest-dev PDMS / ADE4 |
|---|---:|---:|
| B10 | 93.12 / 0.076m | 90.93 / 0.598m |
| B02-opt | 92.75 / 0.077m | 90.88 / 0.599m |
| v1 SF3-terminal | 86.72 / 0.317m | 85.59 / 0.674m |

- head-val에서 ADE가 8배 작았던 것은 학습 장면 기억 때문이다. 같은 이유로 navtrain feature에는 미래 궤적이 기억돼 있어, 분류형(anchor) head는 학습 장면을 외워 실패했다(학습 정확도 100%, 검증 18.8%).
- 근거: README 10/2 절, `evidence/round3_2026-10-03`.

### 5.2 navtest-dev: B\*, 시점, 깊이 (head 4k, seed 17 / 29)
- **B\* 후보(B10 대비 PDMS)**
  - B05-opt −0.03, B03-opt −0.04, B02-opt −0.05(모두 통과)
  - B01-opt −1.19, DAC 악화 1.11로 탈락

- **시점:** first − current = +3.40 / +3.28(CI가 0 미포함). first − terminal = −0.74 [−2.11, +0.41] / +0.61 [+0.06, +1.16]으로 방향이 seed마다 다르다.

- **4k head 결과:** 모두 B10 대비 −3.6 ~ −7.7로 미달. 손실은 주로 DAC(주행 가능 영역)와 EP.

### 5.4 navtest-final (1회, 학생 = SF3 first, 92.6k)

| 모델 | PDMS | DAC | ADE4 | policy p50 |
|---|---:|---:|---:|---:|
| B10 | 89.67 | 97.97 | 0.564m | 797.9ms |
| B\* = B02-opt | 89.65 | 97.93 | 0.564m | 420.7ms |

## 7. 두 벤치마크를 함께 본 해석

1. **시점 효과가 두 설정에서 일관된다.** first ≫ current(NAVSIM +3.3 PDMS, PhysicalAI −0.11m ADE)이고 first ≈ terminal이다. 미래를 노이즈에서 한 번 상상하는 계산이 action 정보를 만들어 내고, 나머지 denoising은 readout에 추가 정보를 거의 주지 않는다. 학생이 1패스로 빠를 수 있는 근거다.
2. **규모 효과도 일관된다.** NAVSIM은 4k → 92.6k에서 격차 −4.2 → −0.4, PhysicalAI는 4k → 20k(표본 100k)에서 미달 → 통과했다. 작은 head가 큰 백본 표현을 읽는 데에도 충분한 학습 데이터가 필요하다.
3. **두 설정에서 판정이 갈린 이유(가설)**
   - 지표: NAVSIM PDMS는 주행 가능 영역 같은 규칙 위반(DAC)에 민감하고, 결정적 평균 예측이 이점을 얻기 어렵다. PhysicalAI ADE/FDE는 평균 예측에 유리하다.
   - 설정: PhysicalAI는 실제 기록이 등록되는 연속 설정이라 기억과 안내가 추가 정보를 준다.
   - 규모: 표본 수는 비슷했다(92.6k 대 100k).
   - 따라서 "PhysicalAI에서 방법이 더 잘 된다"기보다 "지표가 결정적 예측에 유리하다"는 해석을 함께 제시해야 한다.
4. **약점(남은 문제):** NAVSIM의 DAC(주행 가능 영역 준수)와 PhysicalAI의 FDE(4초 끝점). 둘 다 평균 예측이 다봉 분포(예: 갈림길)를 뭉개는 문제와 관련 있을 수 있다(검증 안 함).

## 8. 한계

- 월드모델은 1종(DriveWAM)이다. open-loop / 비반응 채점이다(폐루프 안전성 미검증).
- NAVSIM final은 근소 미통과이고, dev 미통과 상태에서 한 예외 실행이다.
- PhysicalAI의 dev는 무작위 val(D2)이다(공식 test는 VLM 선별 장면). 다만 B10 ADE가 dev 0.821, final 0.802로 비슷했다.
- PhysicalAI 학생의 좌표계 회전(변경 9)은 결과 전에 정했지만, 결과를 크게 좌우했다(없으면 ADE +0.26m).
- 결정적 head와 확률적 생성기의 비교는 평균 오차 지표에서 공정하지 않다(§6.3). 다봉 분포나 안전 지표에서의 비교가 필요하다.
- 증류 기준(action 생성기의 1단계 증류)과 비교하지 않았다. 사용자 결정으로 이번 범위에서 제외했다.
- 지연은 A5000 1장, 공유 호스트 기준이다(비율로 해석). 재는 구간이 벤치마크마다 다르다(§2.4). NAVSIM은 모든 방법에 공통인 VAE 인코딩과 관측 패스를 포함하므로 속도비가 보수적이고, PhysicalAI는 이를 제외한다.
- 서버 정리로 NAVSIM 중간 feature와 전처리본을 삭제했다. NAVSIM 재학습에는 재추출이 필요하다(`evidence/disk_cleanup_2026-10-05/log.jsonl`).

## 9. 선행연구 대비 위치 (확인 필요 — 문헌 조사 전 메모)

- **VPP(Video Prediction Policy, ICML 2025):** 비디오 diffusion 모델의 한 번 denoising 패스 feature로 로봇 정책을 학습한다. "1패스 feature로 action"이라는 아이디어가 가깝다.
  - 차이: 우리는 ① 이미 action까지 생성하는 WAM을 고정한 채 자기 자신의 action 생성기를 대체한다. ② 시점·깊이·기억·언어를 체계적으로 진단한다. ③ 공정한 최소 단계 기준(B\*)과의 속도-품질 비교를 사전등록 protocol로 한다.
- **몇 단계 diffusion 계획(DiffusionDrive 등), consistency/증류 정책:** 속도 문제의 다른 해법이다. 증류와는 직접 비교하지 않았다.
- **diffusion feature를 표현으로 쓰는 연구(인식 분야):** 일반적 배경이다.
- 논문 작성 전에 정확한 인용과 차이를 확인해야 한다.

## 10. 논문 구성안 (제안)

1. 서론: WAM의 action 생성 병목. "상상 1패스면 충분한가?"라는 질문.
2. 방법: 고정 백본, 시점·깊이 readout, SF3 head, B\* 공정 비교, 사전등록 protocol.
3. 실험 1, NAVSIM: 기억 효과로 인한 평가 함정 → 시점·규모 → final(근소 미통과, 0.449 × B\*).
4. 실험 2, PhysicalAI: 연속 주행 → final 통과(0.163 × B\*) → 결정성 대조 → 진단(상상·기억·언어).
5. 분석: 두 벤치마크의 일관된 시점·규모 효과, 지표와 결정성, seed 민감도.
6. 한계와 결론.
