**채택 가능하나 수정 후 실행해야 한다.** DriveWAM과 Light-WAM 공식 코드는 확인되었고, 미래 표현을 추출할 위치와 재사용할 head 모듈도 확인했다. 원본 README를 복사하여 실행하면 NAVSIM 추가 requirements 파일 누락, CLI 불일치, 체크포인트 구조, GPU 메모리, 평가 누락 문제가 발생할 수 있다. `environment.yml`은 고정 commit에 존재한다.

## 3. 발견 사항과 필요한 조치

### A01 — environment.yml은 존재하고 requirements-navsim.txt는 없다

**정정 근거:** 2026-09-30 로컬 Git HEAD가 `abbefb407c9c553f221522fc26077d307620adb4`이고 working tree가 깨끗한 것을 확인했다. `git ls-tree`에는 `environment.yml`이 있으며 `requirements-navsim.txt`는 없다. 기존 “두 파일 모두 없음” 판정은 잘못되었다. [environment.yml](https://github.com/chenshi3/DriveWAM/blob/abbefb407c9c553f221522fc26077d307620adb4/environment.yml), [README](https://github.com/chenshi3/DriveWAM/blob/abbefb407c9c553f221522fc26077d307620adb4/README.md)

**영향:** 없는 requirements 파일을 설치하는 명령은 실패한다. 존재하는 environment 파일에는 모델·NAVSIM 패키지와 별도 PyTorch/FA2 설치 안내가 있지만, 파일 존재만으로 target 서버의 환경 해결·실행 성공이 확인되는 것은 아니다.

**조치:** 기존 environment 파일을 참고 자료와 해시 목록에 추가하고, 후보 모델 환경과 NAVSIM scorer 환경을 분리하는 방침을 유지한다. resolved lock과 import gate를 별도 산출한다. 원천 LingBot requirements는 torch 2.9.0/diffusers 0.36.0/transformers 4.55.2다. 같은 repo의 pyproject는 transformers ≥4.55.4라서 두 파일도 완전히 일치하지 않는다. LingBot 전체를 설치하지 않고 필요한 version을 후보로 고정한다.

**검증:** 2026-09-30 두 환경의 `pip check`, 필수 class/evaluator import, strict checkpoint load, 양쪽 GPU의 CUDA·FA2 forward/backward, NCCL 통과. 모델/평가 freeze를 별도 보관했다.

### A02 — checkpoint CLI 옵션이 문서와 다르다

**근거:** README는 `--checkpoint-path`, actual parser는 `--checkpoint`. [parser](https://github.com/chenshi3/DriveWAM/blob/abbefb407c9c553f221522fc26077d307620adb4/src/navsim/eval.py#L595)

**영향:** README 명령은 unrecognized argument로 실패한다.

**조치:** 계획의 원본 명령은 `--checkpoint`로 수정했다. 신규 runner의 CLI는 help와 문서를 같이 생성한다.

### A03 — 기본 GPU 수 8, backend는 worker에 고정되어 있다

**근거:** `--num-gpus default=8`, `_worker_fn()`은 `attn_mode="flashattn"`. [GPU 기본값](https://github.com/chenshi3/DriveWAM/blob/abbefb407c9c553f221522fc26077d307620adb4/src/navsim/eval.py#L605), [worker](https://github.com/chenshi3/DriveWAM/blob/abbefb407c9c553f221522fc26077d307620adb4/src/navsim/eval.py#L472)

**영향:** A5000 두 장에서 기본 실행 실패. 생성자 기본값을 바꾸는 것만으로 worker backend가 바뀌지 않는다.

**조치:** 처음 `--num-gpus 1`, 통과 후 2. backend는 실제 worker까지 전달하는 새 CLI 옵션으로 만든다. 각 worker는 완전한 model을 복제하므로 메모리는 GPU별로 따로 계산한다.

### A04 — HF weight 폴더와 evaluator가 기대하는 폴더가 다르다

**근거:** HF는 `navsim/{config.json,diffusion_pytorch_model.safetensors}`. evaluator는 `checkpoint_path/transformer`를 연다. [loading](https://github.com/chenshi3/DriveWAM/blob/abbefb407c9c553f221522fc26077d307620adb4/src/navsim/eval.py#L60), [HF tree](https://huggingface.co/chenchenshi/DriveWAM/tree/c4fb6d2c5d26ee3018a9ee1507f36fd02b85b1ce/navsim)

**영향:** HF download root를 그대로 넘기면 config/weight를 찾지 못한다.

**조치:** `drivewam_navsim/transformer`를 HF navsim 폴더로 연결하거나 명시적인 `--transformer-path`를 구현한다. 서버에서 실제 파일 존재를 확인한다.

### A05 — VAE/text base 경로는 실제 local path가 필요하다

**근거:** config의 `lingbot-va/lingbot-va-base`에 `vae/tokenizer/text_encoder`를 join한다. 공식 HF ID는 `robbyant/lingbot-va-base`. [config](https://github.com/chenshi3/DriveWAM/blob/abbefb407c9c553f221522fc26077d307620adb4/src/configs/navsim_cfg.py#L10)

**영향:** 자동 HF resolution을 기대하면 잘못된 repo/path로 접근할 수 있다.

**조치:** pinned asset을 내려받은 서버 절대 local path로 설정을 override한다. fine-tuned checkpoint와 base component provenance를 분리한다.

### A06 — 24GB 한 GPU에 transformer·UMT5·VAE가 동시에 올라간다

**근거:** evaluator init은 세 모듈 모두 같은 `self.device`에 적재한다. [init](https://github.com/chenshi3/DriveWAM/blob/abbefb407c9c553f221522fc26077d307620adb4/src/navsim/eval.py#L46)

**정적 수치와 정정:** transformer payload 11.625GiB, UMT5 파일 합 약 10.582GiB, VAE 파일 약 2.625GiB, 원본 cache 약 0.618GiB. 파일 크기를 GPU 메모리로 그대로 취급하지 않는다. 실제 VAE는 704,688,668 parameters를 BF16으로 적재해 weight 약 1.313GiB다. 세 모델의 BF16 parameter 합계 약 23.52GiB에 KV·activation이 추가된다.

**영향:** 단일 GPU 24GB를 초과한다. GPU 수를 2로 바꾸어도 원본은 replica를 만들기 때문에 해결되지 않는다.

**조치:** 4문장 embedding 선계산 후 UMT5 프로세스 종료. 본 policy에는 embedding tensor만 둔다. 원본 512-token padding과 clean 규칙을 유지한다.

**검증:** 원본 `_encode_prompt()`의 네 문장을 cache로 만들고 encoder를 해제한 합성 fixture B10은 GPU0에서 peak allocated 약 13.67GiB / reserved 약 13.72GiB로 실행됐다. 체크포인트의 누락·예상 밖 key가 없었다. 이후 실제 관측 한 장면도 peak allocated 약 13.67GiB로 통과했고, 현재 관측 전용 입력과 원본 reference 입력의 예측이 비트 단위로 같았다. `evidence/navsim_data_2026-09-30/reports/navsim-real-b10-smoke.json`에 기록했다. 생산용 P01 옵션, feature hook·opt runner와의 parity 및 운영 benchmark는 남아 있다.

### A07 — NAVSIM에는 online scene-evolving Qwen guidance가 없다

**근거:** `_build_prompt()`는 config command 문장을 선택한다. [dataset](https://github.com/chenshi3/DriveWAM/blob/abbefb407c9c553f221522fc26077d307620adb4/src/dataset/navsim_dataset.py#L40)

**영향:** VLM의 125ms를 NAVSIM latency에 더하거나 Qwen을 필수 GPU 프로세스로 넣는 계획은 코드와 맞지 않는다.

**조치:** NAVSIM guidance는 fixed-command embedding으로 고정. PhysicalAI의 VLM·long-horizon memory는 별도 단계에서 검증한다.

### A08 — FlashAttention을 사용하지 않아도 import에서 요구된다

**근거:** `flash_attn_interface` 실패 시 무조건 `flash_attn` import. torch backend는 math SDPA만 강제한다. [attention import 및 SDPA](https://github.com/chenshi3/DriveWAM/blob/abbefb407c9c553f221522fc26077d307620adb4/src/modules/model.py#L29)

**영향:** FA2 미설치 상태에서 CPU/SDPA smoke조차 import 단계에서 실패할 수 있다. `torch` backend의 latency를 fused SDPA 성능으로 오해할 수 있다.

**조치:** A5000은 명시적 FA2 경로, import 실패 시 선택한 backend에서만 에러. 별도 SDPA 모드를 구현하고 backend를 모든 실험에 기록한다. FA3는 Hopper 대상이므로 자동 fallback 우선순위에서 제외한다.

### A09 — solver step 뒤에 cache pass가 추가된다

**근거:** video와 action 양쪽에서 `last_step`에도 transformer를 호출한 후 integration을 건너뛴다. [video/action loops](https://github.com/chenshi3/DriveWAM/blob/abbefb407c9c553f221522fc26077d307620adb4/src/navsim/eval.py#L268)

**영향:** 3+10회라고만 계측하면 추가 연산과 feature 재사용 기회를 놓친다.

**조치:** raw B10/B05는 17/12회로 보존한다. **최종 action cache pass 제거는 필수 효율 비교군**으로 승격한다. B10-opt/B05-opt는 16/11회, B03-opt/B02-opt/B01-opt는 9/8/7회다. 마지막 action pass는 action 값을 갱신하지 않고 단일-chunk predict 종료 시 cache도 지워지므로 생략 전후 trajectory parity를 검사한다. action의 조건을 만드는 마지막 video pass는 제거하지 않는다. PhysicalAI처럼 다음 chunk가 action KV를 쓰는 경로에는 그대로 적용하지 않는다.

학생의 terminal/first/current 경로는 각각 큰 backbone 6/3/1회+head로 구분한다. first는 첫 future forward 직후 solver update 전에, current는 current video primer 직후 zero-action primer 전에 종료한다. full world run에서 수집한 대응 feature와 동일함을 먼저 확인한다. 위 수는 정적 예상치이며 GPU trace·latency 실측을 대체하지 않는다.

### A10 — video sigma의 의미가 원문 단순화와 다르다

**근거:** `denoise_fraction=0.6`은 raw stop 0.4를 만들고 SNR shift 5를 적용한다. [scheduler setup](https://github.com/chenshi3/DriveWAM/blob/abbefb407c9c553f221522fc26077d307620adb4/src/navsim/eval.py#L203)

**영향:** terminal feature를 sigma=0 또는 논문 설명의 0.6으로 잘못 라벨링할 수 있다.

**조치:** actual sigmas를 metadata에 저장. 주 baseline은 공개 코드 설정. 다른 종료 시점은 별도 실험.

### A11 — 원본 dataset은 미래 RGB와 GT action을 함께 반환한다

**근거:** dataset의 selected_images와 actions는 target을 포함한다. predictor는 images의 첫 frame만 인코딩하고 action tensor에서는 shape를 가져온다. [dataset output](https://github.com/chenshi3/DriveWAM/blob/abbefb407c9c553f221522fc26077d307620adb4/src/dataset/navsim_dataset.py#L134), [prediction](https://github.com/chenshi3/DriveWAM/blob/abbefb407c9c553f221522fc26077d307620adb4/src/navsim/eval.py#L406)

**영향:** 본문에 미래 image를 모두 policy에 제공한다고 쓰면 부정확하다. 수정 중 실수로 GT feature를 cache하면 누출이 생긴다. 미래 image를 읽는 I/O도 불필요하다.

**조치:** 관측 전용 input schema, target 분리, 미래 shape/mask는 config 생성. current-only builder로 원본 RGB 변환을 보존한다. future/target permutation invariance 테스트를 필수화한다.

### A12 — action 30차원은 30개 실제 control이 아니다

**근거:** config used channel은 `[0,1,2]`, future_action_steps=8. dataset은 현재 ego frame pose 차분을 정규화하고 evaluator는 cumsum한다. [label construction](https://github.com/chenshi3/DriveWAM/blob/abbefb407c9c553f221522fc26077d307620adb4/src/dataset/navsim_dataset.py#L56), [inverse transform](https://github.com/chenshi3/DriveWAM/blob/abbefb407c9c553f221522fc26077d307620adb4/src/navsim/eval.py#L365)

**영향:** steering/throttle 또는 timestep마다 회전된 body-frame delta로 해석하면 출력이 달라진다.

**조치:** `[B,8,3]` normalized `(dx,dy,dheading)` head를 구현하고 기존 좌표계로 누적한다. meter/radian, heading wrapping, 3s/4s index를 검증한다.

### A13 — 평가가 비활성화되거나 일부 sample만 scoring되어도 실행이 끝날 수 있다

**근거:** PDM import가 실패하면 `_PDM_AVAILABLE=False`. token cache가 없거나 scoring exception이면 `pdm_valid=False`, 최종 평균은 유효 sample만 사용한다. [optional imports](https://github.com/chenshi3/DriveWAM/blob/abbefb407c9c553f221522fc26077d307620adb4/src/navsim/eval.py#L34), [scoring loop](https://github.com/chenshi3/DriveWAM/blob/abbefb407c9c553f221522fc26077d307620adb4/src/navsim/eval.py#L506), [aggregation](https://github.com/chenshi3/DriveWAM/blob/abbefb407c9c553f221522fc26077d307620adb4/src/navsim/eval.py#L586)

**영향:** “evaluation completed”만 보고 full PDMS가 재현되었다고 오해할 수 있다.

**조치:** inference와 official CPU scorer를 나눈다. score를 요청했는데 unavailable이면 fail. count와 token set이 맞지 않으면 주 결과 집계를 중단한다. 실패 sample을 숨기지 않는다.

### A14 — metric cache는 archive 해제만으로 이식되지 않을 수 있다

**근거:** loader는 metadata CSV 첫 파일의 경로 문자열을 그대로 읽는다. [MetricCacheLoader](https://github.com/chenshi3/DriveWAM/blob/abbefb407c9c553f221522fc26077d307620adb4/navsim/common/dataloader.py#L170)

**영향:** 제공자 서버 절대 경로·여러 metadata shard·부분 다운로드 때문에 file not found 또는 누락 발생 가능.

**조치:** 현 root에서 token별 실제 파일을 찾아 index를 재구성한다. 모든 metadata를 병합하고 중복을 검사한다. 단순 glob 순서에 의존하지 않는다.

### A15 — vendored NAVSIM과 official v1.1이 완전히 같지 않다

**검토 결과:** DriveWAM vendored NAVSIM 86개 파일, official v1.1 128개 파일. 공통 파일 중 byte 차이는 5개다. 이 중 3개 config는 newline 차이로 정규화된 text가 동일했다. 의미 있는 차이는 Ray temp-dir 설정과 LQR의 pseudoinverse 연산이다. 여러 `__init__.py`·agent·training 파일도 생략되어 있다.

**근거:** `evidence/navsim_vendor_comparison.json`, `evidence/navsim_vendor.diff`. [DriveWAM LQR 파일](https://github.com/chenshi3/DriveWAM/blob/abbefb407c9c553f221522fc26077d307620adb4/navsim/planning/simulation/planner/pdm_planner/simulation/batch_lqr_utils.py#L121), [official 파일](https://github.com/autonomousvision/navsim/blob/3e8291bfa89ff247231e0227778840cd0a036896/navsim/planning/simulation/planner/pdm_planner/simulation/batch_lqr_utils.py#L120)

**조치:** 주 평가는 official v1.1, 별도 원본 점수 진단. `navsim.common.dataclasses.__file__`와 scorer module path를 실행 로그로 남겨 namespace shadowing을 확인한다. official package와 vendored namespace를 섞어 사용하지 않는다.

### A16 — Light-WAM head는 그대로 붙일 수 있는 작은 독립 모듈이 아니다

**근거:** `StateFusionActionExpert`는 default feature source로 backbone/adapted/delta를 다루고 per-layer 4,608·trunk 6,144를 사용한다. top-level import는 `wan_video_dit`에 연결된다. [head source](https://github.com/L1ziang/Light-WAM/blob/db7d05e724f3eac2d4f0c9c3ac727fe93a44d727/src/lightwam/models/wan22/state_fusion_action_expert.py#L230)

**조치:** 작은 projection 512를 먼저 적용, input은 `backbone`만, output은 `[B,8,3]`. pooler 함수와 필요한 작은 helper를 분리한다. source license 및 수정 내역을 남긴다. MIT notice는 FastWAM/Light-WAM 양쪽 author를 보존한다.

### A17 — learned pooling 학습에는 원본 token이 필요하다

**근거:** pooler attention의 K/V는 정규화된 입력 token이며 query parameter와 같이 학습된다. [LearnedQueryPooler](https://github.com/L1ziang/Light-WAM/blob/db7d05e724f3eac2d4f0c9c3ac727fe93a44d727/src/lightwam/models/wan22/state_fusion_action_expert.py#L125)

**영향:** mean feature 또는 미리 계산한 random-query pooling output만 저장하면 학습 가능한 pooling을 제대로 바꿀 수 없다.

**조치:** probe용 mean cache와 StateFusion용 dense cache 구분. projection까지 학습하려면 projection 이전 feature를 cache한다. compressed feature를 쓰는 경우 별도 방법으로 정의한다.

### A18 — 원본 train launcher는 이번 서버와 연구 범위에 맞지 않는다

**근거:** `scripts/drivewam_navsim_train.sh`는 `--nproc_per_node=8`, 환경의 WANDB 값을 빈 문자열로 덮어쓰고 shell trace를 켠다. train code는 `swanlab as wandb`를 import한다. [launcher](https://github.com/chenshi3/DriveWAM/blob/abbefb407c9c553f221522fc26077d307620adb4/scripts/drivewam_navsim_train.sh)

**조치:** 원본 full fine-tuning을 실행하지 않는다. cache-only head trainer를 새로 만들고 local JSONL logging을 기본으로 한다. 각 GPU에서 독립 head run을 수행하고 shell credential 출력 없이 관리한다.

### A19 — 대규모 RGB PKL 전처리는 중복 비용이 크다

**근거:** original processor는 현재와 future image를 모아 half-resolution array로 scene마다 PKL 저장하며 map/box까지 포함한다. [process_scene](https://github.com/chenshi3/DriveWAM/blob/abbefb407c9c553f221522fc26077d307620adb4/src/navsim/process_data.py#L157)

**영향:** 겹치는 scene의 동일 이미지가 반복 저장된다. raw navtrain 최소 download가 해당 future frame을 모두 포함하는지도 별도로 확인해야 한다.

**조치:** 원본 processor는 소규모 reference check에만 사용. 본 학습은 image path 기반 current-only manifest와 compact label을 사용한다. 정확한 two-stage resize는 유지한다.

### A20 — 공개 checkpoint의 학습 run identity가 충분히 설명되지 않았다

**근거:** README에 논문 PDMS 90.1 및 이후 batch-size 수정 결과 89.9가 공존하고 HF navsim config에는 해당 weight의 학습 step/seed/평가 log가 없다.

**조치:** source와 weight revision을 독립 고정하고 “공개 baseline”을 실측한다. 90.1 또는 89.9 재현이라고 주장하려면 추가 provenance가 필요하다. base weight를 잘못 사용해 missing ego key가 새로 초기화되면 baseline gate 실패로 처리한다.

## 4. 실제 코드 재사용 지도

### DriveWAM

| 파일·함수 | 검토한 역할 | 재사용/수정 |
|---|---|---|
| `src/navsim/eval.py:NavSimEvaluator` | 모델 적재, encoding, rollout | prompt-cache 및 관측 전용 adapter |
| `_prime_rollout_cache` | current video와 zero-action 조건 | current tap; current-only는 첫 video pass 뒤 종료 |
| `_rollout_video_frame` | partial video generation + terminal cache | first/terminal tap; first-only는 첫 update 전 종료 |
| `_rollout_action_chunk` | 기존 teacher action denoising | raw 유지, 단일-chunk opt는 마지막 cache pass 생략 |
| `actions_to_trajectory` | normalization inverse/cumsum | 공통 trajectory 변환 기준 |
| `src/modules/navsim_model.py:WanTransformer3DNavSimModel.forward` | 30개 block loop 및 output projection | block 직후 selected state 추출 |
| `src/modules/model.py:WanAttention` | backend, self-attention KV | 초기에는 state 수집만, KV 확장은 후순위 |
| `src/utils/scheduler.py:FlowMatchScheduler` | sigma/step 규칙 | 그대로 사용, 실제 sigma 로그 |
| `src/configs/navsim_cfg.py` | action/ego/image 계약 | path override와 값 고정 |

### Light-WAM

| 파일·class | 채택 방법 |
|---|---|
| `state_fusion_action_expert.py:LearnedQueryPooler`, 61–199행 | width512 input으로 포팅, query merge 비교 |

head의 출력에는 driving horizon과 ego condition을 새로 연결해야 한다. 로봇 조작용 action normalization·proprioception을 복사하지 않는다.
