# 사전등록: 보완 실험 (2026-11-01)

TMLR 원고 내부 검토(2026-10-31)가 지적한 세 가지를 확인하는 실험이다.

1. B\*를 action step 수로만 골랐다(future pass 수는 3으로 고정).
2. phase 비교(current/first/terminal)를 4k head로만 했다.
3. pass 1 noise를 seed 0으로 고정했다.

이 문서는 아래 실험의 결과가 하나도 나오기 전에 작성했다. 10/2–10/4 실험의 결과는 이미 알고 있다. 체크포인트, 코드, split, 지표, bootstrap 방법은 `사전등록_navtest-dev_2026-10-02.md`(NAVSIM)와 `사전등록_PhysicalAI_2026-10-04.md`(PhysicalAI)를 그대로 따른다. 결과와 관계없이 모두 보고한다.

## 1. 실험 1: 무학습 격자

### 1.1 후보

- 이름은 `V{v}-A{k}`다. v는 future 영상 denoising 단계 수(upstream `num_video_steps`), k는 action denoising 단계 수다.
- 모든 후보는 DriveWAM의 영상 terminal cache pass를 그대로 둔다. 따라서 chunk당 영상 forward는 v+1회다. v=0은 순수 noise latent를 한 번 forward해 cache에 쓰고 바로 action을 denoise한다.
- 모든 후보는 opt다(마지막 action cache pass 생략. 기존 B\*-opt와 같은 변환).
- 새 후보: v ∈ {0, 1, 2} × k ∈ {1, 2, 3, 5}, 벤치마크마다 12개.
- 기존 후보 v=3(B10-opt, B05-opt, B03-opt, B02-opt, B01-opt)은 기존 dev 결과를 그대로 쓴다.
- k=10은 v<3에서 넣지 않는다. forward 수가 현재 B\*보다 많아(NAVSIM B02-opt 6회, PhysicalAI B03-opt 7회) B\*가 될 수 없기 때문이다.
- noise: NAVSIM은 장면별 `sample_seed(token, 0)`, PhysicalAI는 clip별 seed 0으로 기존과 같다.
- 같은 v 안의 action 변형은 영상 단계와 noise를 공유하는 한 번의 rollout에서 계산한다. 각 shard의 앞 4개 장면·clip에서 따로 돌린 결과와 비트 단위로 같은지 확인한다. 다르면 실행을 멈춘다.

### 1.2 품질 선별 (dev)

- NAVSIM(navtest-dev 3,250장면): B10 대비 PDMS 차이 95% CI 하한 ≥ −2.0, NC 평균 악화 ≤ 0.5점, DAC 평균 악화 ≤ 0.5점. paired log-cluster bootstrap 2,000회(seed 17)로 기존과 같다.
- PhysicalAI(dev 1,000 clip): B10 대비 ADE 차이 95% CI 상한 ≤ +0.05 m, FDE 차이 95% CI 상한 ≤ +0.15 m. 기존 cluster bootstrap 2,000회로 같다.
- 기존 v=3 후보의 선별 결과도 같은 코드로 다시 계산해 함께 적는다.

### 1.3 지연 재측정

- 서버에 다른 작업이 없는 상태에서 잰다. 측정 중에는 다른 GPU 작업을 시작하지 않는다.
- NAVSIM: 10/3과 같은 navtest-final 고정 256장면, 장면 단위로 순서를 바꿔 3회, policy 지연(원본 RGB → 궤적, VAE와 관측 pass 포함). GPU 1장에서 단독으로 잰다.
- PhysicalAI: 10/4와 같은 dev 고정 256 clip, 3회, 결정 지연(실제 기록 등록 뒤 영상 단계 + action 단계, 제안 모델은 head). 기존처럼 GPU 2장에 shard를 나눠 동시에 잰다.
- 측정 대상: B10(NAVSIM은 공식 B10, PhysicalAI는 B10-opt), 1.2를 통과한 모든 후보(기존 v=3 포함), 제안 모델(SF3-first).
  - NAVSIM 제안 모델: 92.6k head seed 17
  - PhysicalAI 제안 모델: 20k head seed 17
- 10/3·10/4 측정값은 기록에 남기고, 새 값과 나란히 보고한다.

### 1.4 B\* 재선정과 판정

- 규칙은 기존과 같다. 1.2를 통과한 후보 중 p50이 가장 작은 모델이 B\*다. 동률(0.001 ms 단위)이면 action 단계가 많은 쪽, 그다음 영상 단계가 많은 쪽을 고른다. 지연은 1.3의 새 측정값만 쓴다.
- B\*가 그대로면 final은 다시 돌리지 않는다. 속도 비율만 새 측정값으로 다시 보고한다.
- B\*가 바뀌면 새 B\*를 final에서 한 번 돌린다(NAVSIM navtest-final 8,896장면, PhysicalAI final 1,000 clip). 그다음 기존 판정 규칙을 새 B\*로 적용한다.
  - NAVSIM: `사전등록_navtest-dev_2026-10-02.md` §8. 제안 모델 final 예측은 10/3 것을 그대로 쓴다.
  - PhysicalAI: `사전등록_PhysicalAI_2026-10-04.md` §6. 제안 모델 final 예측은 10/4 것을 그대로 쓴다.
- 기존 판정은 기록에서 지우지 않는다. 새 결과는 "B\* 확장 후 판정"으로 따로 적는다.
- 원고 반영:
  - 새 B\*가 생겨 판정이 바뀌면 속도 주장을 새 B\* 기준으로 고친다.
  - 판정이 그대로면 격자를 표로 넣고 "future pass 수까지 넓혀도 B\*가 같다"고 적는다.

## 2. 실험 2: PhysicalAI 20k `current`와 ego-only

### 2.1 `current` head

- 20k 학습 clip 전부에서 `current` feature를 추출한다. 4k `current`와 같은 코드이고 phase만 `current`다. `current`는 실제 기록 등록 pass의 출력이라 noise와 무관하다.
- head와 학습은 20k `first`와 같다: SF3, 40 epoch, AdamW 3e-4, batch 32, 마지막 checkpoint, seed 17/29/43, chunk 시작 좌표계 출력.
- dev 예측은 batch 1이다. final에서는 돌리지 않는다. phase 비교는 원래 사전등록대로 dev 진단이다.

### 2.2 ego-only head

- 20k `first` head에서 world pooler만 뺀 구조다. ego 입력 5개(속도·가속도 4, 곡률 1), 같은 ego encoder, 같은 fusion·decoder, 같은 chunk 좌표계 회전을 쓴다.
- 학습 행과 학습 설정은 20k `first` head와 같다. seed 17/29/43, dev 예측이다.

### 2.3 해석 규칙 (dev, seed별, chunk-cluster paired bootstrap 2,000회)

- **20k `first` 우위 유지:** 세 seed 모두에서 `current` − `first`의 ADE 차이 95% CI 하한 > 0이다.
- **실질 동등:** 세 seed 모두에서 ADE 차이 CI가 [−0.05, +0.05] m 안에 있고, FDE 차이 CI가 [−0.15, +0.15] m 안에 있다. 이 margin은 B\* 허용치와 같다.
- **판단 보류:** 위 둘 다 아니다.
- 원고 반영:
  - 우위 유지면 phase 주장을 20k 결과로 보강한다.
  - 실질 동등이거나 판단 보류면 "imagination" 주장을 줄인다. 이 경우 제목과 abstract를 고친다.
- ego-only는 판정 없이 `first`·CV 대비 ADE/FDE와 FDE>2m 비율을 보고한다. 제안 모델 성능 중 ego 상태로 설명되는 몫을 보이는 대조다.

## 3. 실험 3: pass 1 noise seed 민감도

### 3.1 PhysicalAI

- dev `first` feature를 noise seed 1, 2로 다시 추출한다. seed 0은 기존 것을 쓴다.
- 학습된 20k `first` head 3개(17/29/43)를 다시 학습하지 않고 그대로 예측한다.
- seed g의 첫 pass noise는 B10-opt seed g의 첫 pass noise와 같다(난수 소비 순서가 같음). 기존 B10-opt seed 0–3 dev 결과와 짝지어 비교한다.

### 3.2 NAVSIM

- navtest-dev 전체에서 generation seed 1, 2(`sample_seed(token, g)`)로 hook한 B10 rollout을 돌린다.
- 같은 rollout에서 B10(g) 궤적과 `first` feature(g)를 얻는다. 92.6k head 2개(17/29)를 batch 1로 그대로 예측한다. seed 0은 기존 dev 결과를 쓴다.

### 3.3 보고와 해석

- head별·seed별 dev 평균 지표를 보고한다. NAVSIM은 PDMS·NC·DAC·ADE, PhysicalAI는 ADE·FDE·FDE>2m이다.
- seed 간 같은 장면 궤적 차이(RMS)도 보고한다. 제안 모델과 B10을 나란히 놓는다.
- **noise 영향 작음:** 모든 head에서 seed 0 대비 평균 지표 변화가 다음 이내다.
  - NAVSIM: PDMS ±0.5점
  - PhysicalAI: ADE ±0.02 m, FDE ±0.06 m
- 원고 반영:
  - "결정적" 표현을 "noise seed를 고정하면 결정적"으로 바꾼다.
  - noise 영향이 작으면 seed 간 변동을 함께 적는다. 크면 그 크기와 B10의 seed 간 변동을 함께 적는다.

## 4. 순서와 데이터

- 실행 순서:
  1. PhysicalAI 3.1 feature 추출 → 예측 → feature 삭제
  2. PhysicalAI 격자와 ego-only. 같은 시간에 NAVSIM 입력 재생성
  3. NAVSIM 격자와 3.2
  4. 채점과 1.2 선별
  5. 단독 지연 측정
  6. B\* 재선정. 필요하면 final 실행
  7. 2.1 추출과 head 학습
  8. 진단 분석
- NAVSIM 입력 재생성:
  - 10/5 정리로 지운 navtest 관측 입력을 같은 sensor blob과 같은 코드(`remote_navtest_prepare.py`의 process 단계)로 다시 만든다.
  - 기존 manifest와 target 파일은 덮어쓰지 않는다. 새 입력 hash는 별도 manifest에 적는다.
  - 내용 확인: 각 shard 앞 장면에서 B02-opt와 제안 모델이 저장된 dev 궤적을 1e-5 안에서 재현해야 한다.
- 디스크:
  - 2.1 feature는 약 193 GB다(여유 243 GB). 3.1 feature는 예측 뒤 지운다.
  - navtest-final 입력은 지연 측정용 256장면만 먼저 만들고, B\*가 바뀔 때만 전부 만든다.
